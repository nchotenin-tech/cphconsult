# เตรียมข้อมูลสำหรับย้ายระบบ

ตอนนี้ระบบใหม่ผ่านการทดสอบอ่านเคสด้วยข้อมูลจำลอง แต่ยังยืนยันไม่ได้ว่าข้อมูลจริงพร้อมย้าย: ยังไม่ได้ตรวจฐานข้อมูลและไฟล์จริง และ schema ใหม่ยังครอบคลุมเพียงบางส่วน อย่านำ backup จริงมา restore ลง cphconsult_dev ที่ใช้อยู่

## เตรียมเป็นสามช่วง

1. **ข้อมูลภาพรวมก่อน** — ระบบเดิม deploy revision ใด, PostgreSQL รุ่นใด, จำนวนตาราง/ขนาดฐานข้อมูล, จำนวนไฟล์/ขนาดรวม, server ใหม่ใช้ OS อะไร CPU/RAM/พื้นที่ว่างเท่าไร และยอมปิดรับการเขียนช่วงเปลี่ยนระบบได้นานเท่าไร ยังไม่ต้องส่งรายชื่อผู้ป่วย รหัสผ่าน หรือ backup
2. **หลักฐานในพื้นที่ส่วนตัวที่หน่วยงานอนุมัติ** — schema-only catalog, ตาราง mapping ทุกตารางและคอลัมน์, บัญชีต้นทางกับ dentist ID, วิธีเปิดใช้งานบัญชีใหม่, manifest ไฟล์พร้อมขนาด/hash และตำแหน่งสำรองข้อมูล การเข้าถึงหรือ export ต้นทางต้องกำหนดขอบเขตและอนุมัติแยกก่อน
3. **ซ้อมและตรวจผลก่อนเปิดจริง** — importer ครบทุก entity ด้วยข้อมูลจำลอง, ซ้อมข้อมูลจริงในฐานใหม่แยกต่างหาก, เทียบจำนวน/IDs/hash/ความสัมพันธ์/ไฟล์, ทดสอบ restore และผู้ใช้ตรวจรับ จากนั้นจึงวาง freeze และ cutover โดยมีการอนุมัติแยก การย้อนระบบหลังระบบใหม่รับ writes ต้องรักษาข้อมูลที่เกิดใหม่ด้วย

ไฟล์แนบต้องมีเนื้อไฟล์จริงด้วย สำรองเฉพาะฐานข้อมูลไม่เพียงพอ และจำนวนตาราง 26 ที่พบใน repository ไม่ใช่จำนวนที่ยืนยันจาก production

## แบบฟอร์มและเครื่องมือตรวจ

คัดลอก template ไปที่โฟลเดอร์ local ซึ่ง Git ignore ไว้:

```powershell
New-Item -ItemType Directory -Force private-data | Out-Null
Copy-Item docs/migration-preparation.template.json private-data/migration-preparation.json
node tools/check-migration-preparation.mjs private-data/migration-preparation.json
```

คำสั่ง Copy-Item ใช้ครั้งแรกเท่านั้น อย่าคัดลอกทับแบบฟอร์มที่กรอกแล้ว โฟลเดอร์ ignored ไม่ใช่การเข้ารหัสหรือการควบคุมสิทธิ์เก็บข้อมูลจริง

- `null` = ยังไม่ทราบ; `false` = ยังไม่ผ่าน; `true` = ผู้รับผิดชอบยืนยันพร้อมหลักฐานแล้ว
- `sourceTableCount` คือจำนวนตารางที่ตรวจจากต้นทาง, `sourceDatabaseBytes` คือขนาดฐานข้อมูลเป็น bytes
- `sourceFileCount` และ `sourceFileBytes` คือจำนวนและขนาดไฟล์รวม; ศูนย์ใช้เมื่อสำรวจแล้วยืนยันว่าไม่มี ไม่ใช้แทนไม่ทราบ
- `targetCpuCores`, `targetRamGiB`, `targetFreeDiskGiB` ต้องเป็นจำนวนเต็มบวก; ให้ปัด RAM/พื้นที่ว่างลงหากมีเศษ
- `allowedDowntimeMinutes` คือช่วงเวลาที่ตกลงได้ ไม่ใช่เวลาที่ทดสอบย้ายสำเร็จแล้ว
- ฟิลด์ลงท้าย Confirmed/Available/Reviewed/Approved/Passed เป็นรายการหลักฐานตามชื่อ เก็บตัวหลักฐานและรายละเอียด OS/version แยกในพื้นที่ที่อนุมัติ ไม่ใส่รหัสผ่าน token connection string ชื่อผู้ป่วย หรือ path ไฟล์ผู้ป่วยลงแบบฟอร์มนี้

เครื่องมือนี้อ่าน JSON ในเครื่องเท่านั้น ไม่เชื่อมต่อฐานข้อมูล ไม่ export/import และไม่แก้ไฟล์ ผลแสดงชื่อรายการที่ขาด/ไม่ผ่าน/ชนิดไม่ถูกต้อง โดยไม่พิมพ์ค่าที่กรอก Exit code 1 = ไม่ครบ, 2 = รูปแบบผิด, 0 = checklist กรอกครบแต่ยังไม่ได้ตรวจหลักฐาน ไม่ใช่การอนุมัติย้ายหรือเปิดระบบ แม้ checklist ครบ การตรวจ schema, reconciliation, restore และ cutover ยังต้องทำจริง

## งานพัฒนาที่ยังคงต้องทำ

ไฟล์ส่วนตัวและสิทธิ์ดาวน์โหลด, ประวัติแชท, clinical mutations ตามสิทธิ์เดิม, audit/idempotency, outbox/realtime, mapping schema เต็ม, importer ที่ resume ได้ และ restore drill ยังไม่เสร็จ เครื่องมือนี้ช่วยรวบรวมสิ่งที่ต้องเตรียม ไม่ทดแทนงานเหล่านั้น
